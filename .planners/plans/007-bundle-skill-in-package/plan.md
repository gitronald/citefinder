# Bundle the use-citefinder skill in the package

## Plan

### Problem

The `use-citefinder` skill is hand-copied into consuming repos, and copies
drift silently. A comparison audit (2026-08) of one downstream copy found
its CLI examples broken against the very version that repo had installed:
it still documented a pre-0.4 shape (`citefinder doi` as Crossref, a
top-level `chapter` command, an `openalex` subcommand) while its lockfile
pinned v0.4.2, where top-level commands are OpenAlex, Crossref lives under
the `crossref` subcommand, and `openalex` no longer exists. Its credential
docs likewise predated `config.toml` support. Nothing reconciles copies in
either direction, and nothing ties a copy's content to the installed
package version.

Depends on [006](../006-update-use-citefinder-skill/plan.md) — settle the
skill's content before making it the packaged source of truth.

### Approach — the planners pattern

Mirror [planners](https://github.com/gitronald/planners): the package is
the source of truth, and anything under `.claude/` is a thin, generated,
version-stamped artifact that an `install` subcommand materializes and can
later re-check for drift.

One deliberate divergence: planners ships seven lifecycle bodies behind a
dispatcher holder (`planners skill <sub>` prints each on demand) because
its bodies change independently of the stub. citefinder has a single
reference body, so the holder and the body collapse into one file — the
generated artifact **is** the full skill, and no `citefinder skill`
print-on-demand indirection is needed.

### Design

1. **Package data.** Move the canonical body to
   `citefinder/prompts/skill.md` (frontmatter included, verbatim). Ship it
   via hatchling — add `artifacts = ["citefinder/prompts/**/*.md"]` (or
   extend the existing sdist `only-include`) so both wheel and sdist carry
   it; load it with `importlib.resources`.
2. **`citefinder install`.** New Typer subcommand that renders the bundled
   body and writes `.claude/skills/use-citefinder/SKILL.md`:
   - **global** mode (default): `~/.claude/skills/use-citefinder/` —
     serves every repo when the CLI is installed as a tool.
   - **`--local`**: `<repo>/.claude/skills/use-citefinder/` — for repos
     that vendor the skill (this repo included).
   - The render inserts a stamp comment immediately after the
     frontmatter: `<!-- generated by citefinder X.Y.Z (mode=global); do
     not edit — run: citefinder install --force -->`. The stamp is how
     `--check` recovers the mode and how a generated file is told apart
     from a hand-authored one.
   - Refuse to overwrite a file that lacks the stamp unless `--force` —
     never silently clobber a hand-edited skill.
3. **`citefinder install --check`.** Reports `ok`, `drifted` (installed
   artifact differs from the current render), or `missing`, mirroring
   planners' check UX. Exit non-zero on drift/missing so it can gate CI or
   scripts.
4. **Dogfood.** Replace this repo's hand-maintained
   `.claude/skills/use-citefinder/SKILL.md` with the output of
   `citefinder install --local` — the file's content should be
   byte-identical to today's skill plus the stamp line. From then on, skill
   edits happen in `citefinder/prompts/skill.md` and are re-materialized.
5. **Sync story for consumers.** Documented in the README and the skill
   itself: upgrade the package, then `citefinder install --check` →
   `citefinder install --force`. A consuming repo's copy can no longer
   drift from its installed version without `--check` saying so.

### Non-goals

- No multi-skill dispatcher, no `{cli}` invocation-token rendering, and no
  pre-commit hook wiring — planners needs those for its seven-body
  lifecycle tooling; a single reference skill doesn't.
- No auto-install on import or on CLI startup; materializing `.claude/` is
  always an explicit user action.

### Tests

- Rendered artifact = bundled body + stamp line after frontmatter;
  frontmatter (name/description triggers) preserved verbatim.
- Path resolution per mode (global under monkeypatched `HOME`, local under
  `tmp_path` repo root).
- `--check` returns each of `ok` / `drifted` / `missing` in a `tmp_path`
  sandbox.
- Overwrite refusal on an unstamped file; `--force` proceeds.
- Bundled body is loadable via `importlib.resources` from an installed
  wheel context (guards the hatchling include).
